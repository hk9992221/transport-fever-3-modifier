# 安全软件报警与发布方式

本项目是游戏进程修改器。报警应先核对实际文件和风险名称，不能仅凭工具名称或源码可见就认定误报。

## 当前代码中能确认的行为

- 游戏连接使用 `OpenProcess`、`WriteProcessMemory`、`CreateRemoteThread` 和 `LoadLibraryW`，把 `TransportFever3Runtime_v6.dll` 加载到游戏进程；运行模块使用 MinHook 挂钩已验证的 Lua 接口。这些行为属于修改器功能，也可能触发安全软件规则。
- Portable 是自释放启动程序，释放主程序及依赖后，再启动图形主程序。
- v1.1.7 的普通界面启动不再自动连接游戏。只有点击“连接游戏”，或明确使用已有的实时采集/脚本命令行模式，才会发起游戏连接。
- Setup 安装后直接运行已安装主程序，不使用 Portable 启动器。安装采用当前用户目录、不请求管理员权限，支持正常卸载；各版本文件分开存放，更新不会覆盖游戏正在使用的旧 DLL。
- 构建记录发布文件的 SHA-256 和实际 Authenticode 签名状态。目前没有配置可信代码签名证书；不能把 SHA-256、编译通过或离线检查当成杀毒检测通过。

游戏连接仍沿用现有实现。Setup 与明确连接时机便于核查行为；它们不保证连接游戏时不被拦截。当前尚未对发布二进制执行 360 实测或提交厂商复核。

## 根据报警阶段定位

| 报警阶段 | 需要核对的内容 |
| --- | --- |
| 下载后、尚未运行 | 下载的 EXE 是否与该版本 Release 的哈希一致；具体风险名称。此时尚未执行游戏连接。 |
| 打开 Portable | 被报的是外层 Portable EXE、释放出来的图形 EXE，还是运行模块。 |
| 打开 Setup 安装后的程序 | 完整文件路径及风险名称；正常打开界面没有自动游戏连接。 |
| 点击“连接游戏”后 | 被报主程序还是运行模块，以及风险名称是否指向进程修改、加载或挂钩。 |

360 官方提供[开发者误报反馈入口](https://open.soft.360.cn/report.php)，其[帮助页](https://open.soft.360.cn/guide/guide_1.php?i=3)说明非注册厂商也可以提交处理。复核应使用**实际被报的同一文件**，附完整风险名称、报警截图、文件哈希、版本及复现步骤；不要把不同版本或不同层的 EXE 混为同一样本。

Microsoft 的 [`CreateRemoteThread` 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createremotethread)说明该 API 会在另一进程地址空间创建线程；这里的行为描述与源码一致，不代表 Microsoft 或 360 已认可本项目。

仓库是私有的，构建流程不会自动将软件、源码或日志上传到第三方扫描平台。后续厂商复核需要针对实际报警文件另行提交。
