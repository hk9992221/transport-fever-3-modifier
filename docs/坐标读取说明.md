# 建筑坐标读取与货物页调整（v1.1.6）

截图中的“镜头已读取”说明当前镜头中心已取得；后半段提示来自兼容库存的建筑位置缺失。它与库存容量是两项独立检查。截图中的煤矿显示“已满”，因此本次预计添加 0 件，添加按钮不可用；修复坐标后也不会向已经满的库存继续添加。

## 已确认的代码问题

旧版从 `Warehouse/Industry.construction` 取得建设实体，读取 `CONSTRUCTION.transf`，随后只尝试 `api.type.Mat4f.getTransl`、`api.type.Mat4f.cols` 和实例 `cols`。这些入口缺失、不可调用或未通过保护性可调用检查时，就没有其他读取路径。

游戏官方接口文档明确规定：

- [`Construction.transf`](https://wiki.transportfever3.com/script-doc/api/engine.html#enginecomponentconstructiontransf) 是建筑的**世界变换**。
- [`Mat4f`](https://wiki.transportfever3.com/script-doc/api/type.html#mat4f) 支持 16 项列主序的 `mat[i]` 访问；第四列为平移列。`cols` 使用 1–4 列索引，`getTransl` 返回平移向量。
- [`Warehouse`](https://wiki.transportfever3.com/script-doc/api/engine.html#enginecomponentwarehouse) 和 `Industry` 有 `construction`、`stockList`；`Town` 本身没有这两个字段。推荐范围限定为仓库与产业，不再把城镇实体当成有建设矩阵的库存。

v1.1.6 增加实例 `getTransl`，以及 `transf[13]`、`transf[14]` 的平移读取。读取下标时先验证 16 项均为有限数，并验证仿射矩阵末行为 `0, 0, 0, 1`，不会把错误布局、缺失值或非数值当成 `(0, 0)`。这使用 Lua 暴露的矩阵元素，不涉及猜测进程内存偏移。

截图只包含简化提示，无法进一步确定当前游戏是缺少辅助方法、方法绑定方式不同，还是可调用检查未通过。新诊断会保留每条失败路径、建设实体编号与矩阵类型；成功时记录具体 `positionSource`。导出诊断中各库存保留这些字段。

## 界面问题与调整

旧版右侧把教程式标题、说明、推荐卡片、目标、数量和收藏串成很长的表单，造成普通窗口也出现内部滚动条；货物表格的第二列又重复显示“货物”。字体与边界分别经历 DPI 更新时，也可能出现侧栏较小、页面字号偏大的情况。

新版把搜索与筛选放回左侧货物列表，右侧只显示接收建筑和必要反馈；数量与添加按钮固定在底部。推荐和定位合并为一行，去掉重复说明、大推荐卡片和重复分类列。页面在创建句柄前保留基准字号，布局时根据窗口当前 DPI 统一恢复字号；按钮按实际字体测量。窄窗口使用单列滚动，操作区保持固定。窗口继续支持 16:10 等比拖动、最大化与还原。

切换货物时，原目标若已满，优先选择有空位的兼容建筑；用户手动选择的目标在普通刷新和镜头移动时保留。坐标不可用仍允许手动选择有空位的库存。

## 验证边界

Lua 模拟验证覆盖类型方法、实例方法、受保护可调用对象、只支持数字下标的原生对象、负坐标与旋转矩阵、缺失项、NaN、无穷值和非法仿射矩阵。坐标失败不阻断手动添加；原有容量裁剪、异步确认、重复请求和地图隔离检查保留。

Windows 打包工作流中的离线检查增加固定数量区、添加按钮、普通尺寸的详情可见性、字号恢复，以及更换货物后避开满库存的检查。离线检查与模拟不能替代当前游戏构建中的实际读取和界面验证。工作流仍只手动触发，发布单文件便携 EXE。
