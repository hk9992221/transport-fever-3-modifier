狂热运输3修改器 · v1.1.7

使用方式
1. 推荐从 Releases 下载 setup.exe，按提示安装；也可选择 Portable 单文件便携版。
2. 启动 Transport Fever 3，进入加载完成、可正常操作的地图。
3. 从开始菜单打开安装的修改器；Portable 则双击下载的 EXE。所有必需文件都随安装包或便携版提供。
4. 打开界面不会自动连接游戏。进入地图后点击“连接游戏”；已经连接时按钮显示“刷新游戏”。
5. 游戏和修改器使用相同权限。更新运行模块后应完全重启游戏。
6. Setup 通过 Windows 已安装应用卸载；Portable 关闭后可删除下载的 EXE。卸载不删除个人设置，彻底清理时再手动删除下述配置和缓存。

运行环境与兼容连接
Windows 10/11 x64，系统 .NET Framework 4.8。
界面采用紧凑的浅色布局，内部控件统一按主窗口 DPI 排版。常用功能按宽度排列为 1–3 列，通常为双列；修复滚动重排后顶部出现大块空白。主页面导航固定在左侧，右侧内容独立滚动；连接与关闭功能按钮位于侧栏底部。普通窗口可拖动边缘或角落自由缩放，内容保持 16:10；支持最大化和还原，最大化时按相同比例居中适配并留白。初始尺寸以 1280×800 为基准适配屏幕工作区域和 DPI。按钮按字体测量，说明文字自动换行；屏幕空间较小时切换布局并提供滚动。
游戏版本或构建号变化时尝试兼容连接，按实际入口与功能接口验证结果开放功能。未通过的接口会给出原因。
运行模块核对 Lua 接口与结构锚点；接口检查通过不代表所有游戏功能均已实测。
通信协议冲突、旧版模块驻留及进程身份检查保留。切换存档或重新启动游戏后需要重新确认连接。

功能与恢复
保留公司财务、产业建设、载具运输、日历模拟等 19 项常用功能，以及货物目录、城镇与产业管理、镜头与书签。
持续功能关闭后提交恢复命令；“关闭全部功能”关闭全部持续功能。断开连接后的恢复需游戏继续运行并处理更新。
资金、贷款、等级、经验、日期、货物、土地容量等一次性操作会影响存档，关闭开关不会撤销；需要撤销时加载操作前的存档。
结余不减按开启时的账户下限补回；免费用仍需具备原购买资金；收入倍率补发游戏确认的收入差额。
公司等级接口只向上提升。产业不关闭同时暂停产业自动升级、降级和关闭。
载具参数作用于当前公司，新增加的载具与产业会补充应用。
模拟倍率使用整数。日期格式 YYYYMMDD，校验月份与闰年；暂停日历优先于日历倍率。
乘客属于人口模拟，不作为货物添加；货物需要兼容且有剩余容量的目标库存。数量超出时自动按剩余空间添加；已经满的库存不再新增。

货物添加操作
左侧为搜索与货物列表，右侧为接收建筑。数量和添加按钮固定在底部，右侧去掉重复说明和大推荐卡片；较小窗口使用单列滚动。DPI 变化后恢复一致的逻辑字号，避免页面字体与侧栏大小不一致。
1. 选择或勾选货物，批量添加最多 64 种；数量是每种货物的期望添加数。搜索与筛选保留勾选，可用“清空勾选”重选。
2. 点击“推荐附近建筑”，工具会主动读取游戏当前镜头并刷新库存位置，再选择最近、兼容所选货物且尚有空位的仓库或产业。无需先打开镜头页面。移动镜头后可再次点击；其他刷新不会改变手动目标。更换货物时，如果原目标已满，则优先选择有空位的兼容建筑。
3. 查看预计数量并点击页面底部的“添加货物”。剩余空间不足时自动调整数量，多种货物共同占用的容量会统一计算。
4. 提交后等待游戏执行，界面显示实际添加数量。等待时仍可搜索、滚动详情、选择库存和调整下一次的数量，执行按钮等确认后恢复，避免重复提交；加载另一地图时清除旧选择。
5. 如果游戏显示 0x，提交后请回到游戏恢复运行，等待库存操作确认。工具不会替你改变游戏暂停状态。
镜头读取失败时仍可点击重试；建筑坐标依次尝试类型方法、实例方法及世界变换矩阵下标读取；矩阵下标读取会验证全部 16 项和仿射末行。读取不到时仍可手动选择库存并添加。诊断页显示坐标来源、建设实体和具体失败原因。详情滚动位置不会被常规状态刷新重置。名称修改中尚未提交的输入会在刷新时保留。

镜头读取
“镜头书签”中的“读取当前镜头”会主动请求游戏端数据，再更新数值；“保存当前镜头”也先读取再保存，避免保存旧快照。
读取与修改接口分别验证。只有有效中心坐标时可用于库存推荐；保存书签和应用位置需要完整的距离、旋转和俯仰参数。读取不会改变游戏镜头。

本机设置
Setup 安装文件位于 %LOCALAPPDATA%/Programs/TransportFever3Modifier/versions/ 下各版本目录，开始菜单打开本次安装的版本；升级不覆盖游戏仍加载的旧 DLL。Setup 的个人设置保存在 %LOCALAPPDATA%/TransportFever3Modifier/UserData/配置/用户设置.json。
从原 Portable 改用 Setup 时，如需保留原设置，可将原 EXE 旁“配置”目录复制到上述 UserData 目录。
快捷键、收藏、最近使用与镜头书签保存在便携 EXE 旁的“配置/用户设置.json”，保存设置时自动创建。
如果 EXE 所在目录不可写，设置使用 %LOCALAPPDATA%/TransportFever3Modifier/UserData/配置/。
持续开关不会自动重开。升级时将新版 EXE 放在原目录，即可沿用设置；移动时可将“配置”目录一起复制。
运行文件缓存位于 %LOCALAPPDATA%/TransportFever3Modifier/portable/，按内嵌资源内容区分目录。不同版本不会覆盖游戏仍在使用的旧模块；游戏完全退出后可以删除缓存，下一次启动会自动恢复。
书签对应创建时的地图，请在相应地图使用。便携包不包含开发机的个人设置或备份。

游戏名称与自定义显示名称
世界管理和目标库存优先使用游戏 getEntityName 返回的完整名称，其次读取名称组件；不会为缺省名称拼接实体编号。
游戏支持改名时，在世界管理中编辑名称并点击“保存到游戏”；工具会等待游戏回读确认。请在游戏中保存存档以保留改名。
读不到游戏名称时，可以点击“保存显示名称”，该名称只用于本工具的当前地图会话，不修改游戏；游戏名称一旦可读，仍优先显示游戏名称。
显示名称按游戏进程和地图会话隔离；重新启动游戏或加载其他地图不会套用上一地图的名称。

自动构建检查范围
“发布清单.json”记录本次构建的版本、架构、源码提交及文件 SHA-256。
工作流执行源码编译、x64 PE、版本、Lua 一致性与离线布局校验。默认 Setup 还在隔离 runner 中实际安装、校验文件、运行已安装程序的离线检查并卸载；选择 Portable 时检查其实际释放资源。便携 EXE 单独放入含中文与空格的目录启动，使用临时缓存和设置目录。检查不连接游戏，不声明已实测游戏功能。
便携 EXE 内嵌主程序、运行模块、使用说明、第三方许可及发布清单；源码保存在 GitHub 仓库。构建不生成 ZIP 发布附件。Actions 默认发布 Setup，可手动选择 Portable。
本地构建默认生成 portable.exe 与 .sha256；加 -Folder 仅输出可运行文件夹，旧参数 -SkipZip 仍可使用。构建日志会标明失败阶段和源码提交；清理临时文件被占用时单独提示，并在可读时显示占用该临时模块的游戏 PID。

安全软件报警
游戏连接使用 DLL 加载、进程修改和接口挂钩，可能被安全软件拦截。Setup 安装后直接运行已安装的主程序，普通启动不会连接游戏；点击“连接游戏”才访问游戏进程。当前没有配置可信代码签名，哈希或离线检查不能替代安全软件扫描，不能保证不报警。请核对实际被报的文件名、完整路径、风险名称与哈希；官方复核入口：https://open.soft.360.cn/report.php 。本项目不会自动向第三方扫描平台上传私有软件。
