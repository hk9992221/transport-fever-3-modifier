# 产业推荐功能规格（v1）

- 状态：待实现；本文是开发与验收依据。
- 日期：2026-10-30
- 适用仓库：`hk9992221/transport-fever-3-modifier`
- 基线：`main@71f61fff835fb67e10dc8684b386a85c6a478e7a`，包含 PR #1 的镜头读取稳定性修复。
- 页面名称：**产业推荐**
- 交付范围：增加独立页面，按当前地图的真实生产与消费关系，帮助玩家选择产业链的上下游和供给城镇。

## 1. 用户要解决的问题

玩家准备建设一条产业链时，需要回答：我选中的这座产业缺哪些原料、地图上谁生产这些原料、各处离它多远；它生产的每种产品可以运到哪些产业或城镇，以及如何直接在游戏里找到这些地点。

以“某地畜牧场”为分析起点，假设当前游戏规则中它消耗小麦、产出肉和羊毛：

1. 在“原料供应 → 小麦”中列出当前地图上**全部生产小麦的产业**，包括每座农场的名称、类型、与该畜牧场的距离和“定位建筑”操作。
2. 在“产品去向 → 肉”和“产品去向 → 羊毛”中，分别列出**全部消耗该产品的产业**。
3. 对能供给城镇的产品，同时列出符合当前地图需求规则的**全部相关城镇**，展示距离并支持定位。
4. 对任意相关产业点击“查看产业链”，可以继续分析它自己的原料与产品，再返回上一座分析建筑。

“畜牧场需要小麦、产出肉和羊毛”以及“肉、燃料、木板、沙发等可供给城镇”是说明交互的例子。**实际配方、货物名称和城镇供给资格必须读取当前游戏、存档及模组生效后的规则，不能把这些例子写成固定配方。**

## 3. 页面与操作流程

### 3.1 页面结构

页面沿用现有浅色主题、字体、图标、按钮和 DPI 适配规则。

| 区域 | 内容 |
| --- | --- |
| 顶部选择区 | “手动选择建筑”“镜头推荐”“刷新产业数据”，以及索引刷新状态。 |
| 当前分析卡片 | 建筑名称、产业类型、等级（可读时）、原料/产物标签、“定位当前建筑”“返回上一分析”。 |
| 原料供应 | 按原料分组，每组显示货物名、候选总数及完整供应产业列表。 |
| 产品去向 | 按产物分组，每组显示下游产业与供给城镇两个独立区域及各自数量。 |
| 状态反馈 | 数据更新时间、正在读取、部分数据未读取、无匹配结果等必要信息。 |

普通宽度可将“原料供应”“产品去向”并排；窄窗口改为纵向排列。每种货物都必须在页面上有名称和数量入口，不得只展示第一种产物、丢掉副产品。货物分组可以折叠，但当前展开组要能完整浏览全部结果。

无城镇用途的产物显示“该产品未识别到城镇供给用途”；有城镇用途但当前没有匹配城镇时显示“当前地图暂无已确认需求的城镇”。无法读取需求时显示读取失败状态，不能显示为没有需求。

### 3.2 手动选择建筑

选择器至少包含：

- 一级：**全部产业 / 具体产业类型**，例如农场、畜牧场、锯木厂等；具体类型与数量随地图动态生成。
- 二级：该类型下的具体建筑，显示名称和产业类型，可按名称排序。
- 搜索：匹配游戏名称、本机显示名称、产业类型，以及已识别的输入/输出货物。
- 货物方向筛选：全部 / 消耗该货物 / 生产该货物，便于搜索“工具”后直接找生产工具的建筑。
- 分类计数与匹配计数，例如“农场（23）”“当前匹配 8 座”。
- 一键清除筛选，恢复全部产业。

产业类型优先读取建设资源的本地化类型名，以稳定资源标识分组。名称中的地名、玩家改名不参与产业类型判断。无法识别具体类型时归入“其他产业 / 类型未识别”，仍可选择和分析。

**仅按“产业 / 城镇”分类不满足本需求。** 普通仓库、车站和城镇不混入产业起点列表。当前没有产量、缺少原料、库存为零或库存已满的产业仍须列出。

同名建筑通过类型、有效坐标或已计算距离辅助区分；不把原始实体编号拼到所有名称后面。实体编号保留在诊断详情中。

### 3.3 镜头推荐

1. 用户点击后，主动请求当前镜头中心和可用的产业位置；不要求先进入镜头书签页读取。
2. 推荐范围为当前选择器的分类与搜索结果；界面标明“在当前筛选范围内推荐”，默认筛选范围为全部产业。
3. 在具有有效坐标的候选中，按与镜头中心的平面直线距离选择最近的一座。距离相同使用稳定的名称、实体键排序。
4. 仅有有效中心坐标即可推荐，不要求完整的镜头距离、旋转、俯仰参数。
5. 推荐选中的建筑只用于分析，不自动移动游戏镜头。
6. 读取失败、没有候选、全部候选坐标不可用分别说明原因，不把旧镜头样本默认为当前读数。
7. 用户随后手动选择其他建筑，或在游戏中移动镜头，不自动覆盖当前选择；只有再次点击推荐才重新选择。

这里推荐的是**产业分析起点**，不得复用货物添加页“能接收所选货物且还有空位”的筛选条件。

### 3.4 定位与继续分析

每个产业结果提供两个不同动作：

- **定位建筑**：将游戏镜头定位到该产业，当前分析起点和结果列表保持不变。
- **查看产业链**：把该产业设为新的分析起点，重算它的上下游，保留上一页的筛选、所选货物、滚动位置。

城镇结果提供“定位城镇”。首版城镇作为消费终点，不要求切换为产业分析起点。

“返回上一分析”恢复上一分析页面；与现有“返回上一镜头”分别处理，不能共用一份历史。多次查看产业链可以形成访问历史；相邻重复选择同一建筑不重复入栈。图中有循环生产关系时，也不得递归展开至卡死。

## 4. 匹配语义

### 4.1 以真实规则判断生产和消费

核心关系如下：

- 某产业的生产规则输出货物 `c`，它才是 `c` 的供应候选。
- 某产业的生产规则消耗货物 `c`，它才是 `c` 的下游消费候选。
- 城镇的生效需求规则包含货物 `c`，它才是该货物的城镇供给候选。
- 普通库存允许存放 `c`，只能证明库存兼容，不能证明生产或消费。

不得用货物当前库存量、库存槽 `allowed`、建筑名称关键字或过去是否运输过该货物代替配方判断。年产量暂时为零也不取消它的供应关系。

原料与产物必须来自当前生效的生产规则。配方包含“二选一”等替代原料时，保留替代关系；增产材料要标明“可选 / 增产材料”，不能一律标为开工必需。相同货物出现在多条规则中时，货物分组去重，详情保留规则来源。

数量或配比只有在单位与含义可验证时才展示；未读到时显示“配比未读取”，不补零，不推算年产量。当前等级可用规则与升级后可能规则不能混在一起冒充当前需求；不能验证的未来规则留待扩展。

### 4.2 原料供应

对当前建筑的每种输入货物，枚举地图中所有输出该货物的产业：

- 按候选产业实体去重，排除当前分析实体自身。
- 同一产业通过多条规则生产该货物，在该货物列表中只出现一次。
- 候选属于其他产业类型时也应显示，不把“小麦供应”写死成名为“农场”的类型。
- 不按半径、库存、生产率、是否已有线路等条件默认隐藏候选。

### 4.3 产品去向

对每种输出货物分别展示：

1. **下游产业**：所有将该货物作为必需原料、替代原料或增产材料的产业，并标明对应角色。
2. **供给城镇**：所有依据当前地图规则确认可供给的城镇，按第 5 节展示需求状态。

同一产业消耗两种产物时，可以在两种产物的列表中分别出现；同一货物列表内不可重复。同一城镇在同一货物下只显示一次，多个需求区合并到一行详情。

### 4.4 “全部”与推荐排序

“推荐”的首版含义是**把完整候选按距离排好，帮助玩家选择**：

- 默认展示全部匹配候选，不只返回最近 3/5/10 家，不预设最大距离。
- 最近候选可以有“最近”标记，但其余候选必须仍可浏览。
- 默认按有效距离升序；距离未知者放在末尾，使用稳定名称和实体键作次级排序。
- 可提供名称排序与用户主动设置的距离筛选；筛选必须可见、可一键清除。
- 大列表可虚拟化或分批加载，必须显示总数与加载进度，所有结果都可获取，不得用隐藏条数上限实现“优化”。
- 数据读取不完整时显示“已确认 N 个，仍有 M 个待读取”，不能把 N 宣称为全地图完整总数。

## 5. 城镇供给规则

城镇是必需范围，不能因现有货物添加页没有城镇库存而省略。

| 状态 | 列表行为 |
| --- | --- |
| 当前需求已确认 | 正常展示城镇与需求区；需求量可读且含义明确时附上。 |
| 可供给，但当前需求为零或尚未启用 | 在规则确实能证明该资格时仍显示，标注实际状态；可分组，不冒充当前缺货。 |
| 需求读取失败 / 无法确认 | 展示未完成提示和待核验数量；不列成“已确认消费者”，也不据此宣布没有城镇。 |
| 明确不接收该货物 | 不列入该货物的已确认城镇候选。 |

肉、燃料、木板、沙发以及其他游戏/模组增加的货物统一走这套逻辑，不维护仅包含这些例子的白名单。

同一城镇的住宅、商业、工业需求按货物合并，详情说明需求区。库存、容量、年消费、供给比例都是不同含义；无法验证具体字段含义时不显示“缺货量”或“可送数量”。

全局“城镇可能需要的货物”映射只能提示潜在用途，不能直接推出每一座城镇当前都需要这种货物。

## 6. 距离、坐标与定位

### 6.1 距离基准

- 镜头推荐阶段：**当前镜头中心 → 候选产业**。
- 上下游结果：**当前分析建筑 → 供应/消费产业**。
- 城镇结果：**当前分析建筑 → 对应货物的城镇需求区参考中心**。

定位候选后，结果仍以原分析建筑为基准，不能悄悄改成相对新镜头的位置。

产业间使用世界坐标的二维欧氏距离：

```text
distance = sqrt((target.x - anchor.x)^2 + (target.y - anchor.y)^2)
```

显示统一为“直线距离”；小于 1000 米显示整数米，否则显示 1 位小数的千米。排序使用原始数值，不用四舍五入后的文字。该数值不表示公路/铁路里程、运送时间、已有连接或可达性。

### 6.2 产业位置

复用现有 `stockPosition` 的建设世界变换读取与矩阵校验思路。即便产业库存信息不完整，也应独立尝试通过产业的建设实体读取位置，不因为未生成有效库存行而漏掉整个产业。

无效、NaN、无穷值和读取失败均表示位置未知，不能替换成 `(0, 0)`；真实零坐标、负坐标必须正常支持。

### 6.3 城镇位置

城镇自身不按产业的 `construction / stockList` 方式取位置。首版采用可验证的城镇需求区中心：

1. 根据该货物匹配到的住宅、商业、工业需求区，读取对应区中心。
2. 一座城镇有多个相关需求区时，以其中到分析建筑最近的中心作为该货物行的参考点。
3. 距离列或提示明确标为“至需求区中心（直线）”，详情记录采用的需求区。
4. 相关需求区坐标读取不完整时标明不完整，不把缺失位置当零坐标或隐藏城镇。
5. 该参考距离不代表城镇具体卸货站点的运输距离。

### 6.4 定位执行

优先复用现有 `focus` 能力。产业传产业实体，城镇传城镇实体，不把库存实体误当建筑实体；调用前检查地图作用域、实体存在和定位能力。

镜头位置保存、返回与修改继续遵守 PR #1 的完整镜头参数校验。仅有中心坐标时仍可计算距离与浏览关系；定位所需能力不可用时禁用定位按钮并给出原因，不阻塞分析页面。

坐标读取与 `focusEntity` 是独立能力：候选坐标未知但实体定位能力有效时，允许“定位建筑 / 定位城镇”。定位失败保留当前分析、筛选和列表，不自动重试导致镜头连续跳动。

## 7. 结果行与信息展示

| 字段 | 产业结果 | 城镇结果 |
| --- | --- | --- |
| 名称 | 游戏名称，缺失时沿用现有本机显示名称和名称回退逻辑 | 同左 |
| 类型 | 具体产业类型 | 城镇 |
| 对应货物 | 当前分组的原料或产物 | 当前产物 |
| 关系 | 生产该原料 / 消耗该产品；可选时注明 | 当前需求 / 可供给但当前未启用 |
| 距离 | 相对分析建筑的直线距离 | 至对应需求区中心的直线距离 |
| 操作 | 定位建筑、查看产业链 | 定位城镇 |

当前建筑名称和距离基准应始终可见。同名对象增加必要位置辅助信息；内部路径、原始配方数组、实体编号和读取异常栈进入诊断，不堆在主要操作界面。

搜索、切换原料/产物、滚动列表时保持响应；常规刷新不重置列表滚动、手动选择和正在输入的搜索文字。

## 9. 数据读取依据与待验证项

### 9.1 已查到的官方入口

以下入口用于确定实现路线，仍需在实际游戏构建验证可调用性和返回结构：

| 用途 | 官方入口 / 数据 |

1. 记录一个基础原料产业、一个多原料加工产业、一个多产物产业的真实返回样本，对照游戏界面确认方向正确。
2. 记录至少一种可选增产/替代输入（游戏或测试模组提供时），确认没有误标必需原料。
3. 记录至少两座城镇的需求、相关区中心以及一种可供给成品，对照游戏界面确认需求语义。
4. 验证当前等级、停产、无库存、模组配方变化与数据不可读时的行为。
5. 对每个新增受保护可调用入口补充验证路径；不可用时降级为“未读取”，不猜偏移、不假造关系。

## 10. 内部数据契约（建议，非现有接口）

以下名称是拟新增的应用内部协议，不是游戏现有 API。

### 10.1 索引元信息

周期状态只携带 `industryIndex` 的轻量元信息：

```json
{
  "schemaVersion": 1,
  "world": 1,
  "nameScope": "current-map-session",
  "revision": 12,
  "complete": true,
  "industryCount": 320,
  "townCount": 28,
  "generatedAt": 1234.5,
  "unreadIndustryCount": 0,
  "unreadTownCount": 0
}
```

计数与实体示例均为测试数据。成功读到的空列表与读取失败必须分开；缺字段不等于零。

### 10.2 规范化实体

每座产业至少包含：

- `entityId / constructionId / stockListId`：真实实体关系，不混用。
- `typeKey / typeName`：稳定类型键及本地化显示名。
- `gameName`、用于现有名称回退的字段。
- `position / positionStatus / positionSource`。
- `recipeStatus`：verified / partial / unavailable。
- 规范化输入与输出货物 ID 集合，及可用的规则角色、替代组和数量说明。
- 可读时的产业等级与运行状态。

每座城镇至少包含实体、名称、规范化货物需求、需求区及可用区中心，以及各项读取状态。候选记录含关系方向、货物 ID、目标实体、距离或 null、匹配依据。

所有货物匹配使用货物 ID，不能用中文名连接；不同模组的重名货物不能被合并。产业与城镇 ID 使用明确的实体种类及当前地图作用域区分。

### 10.3 请求与响应

建议新增：

- `industry_catalog`：获取分类及可搜索产业目录。
- `industry_relations`：获取指定分析建筑、货物、方向的完整候选集合，按需分批。
- `industry_refresh`：显式刷新索引。

每次请求和响应都关联 `request`、`world`、`nameScope` 和索引 `revision`；关系响应还关联分析建筑及货物。快速切换分析建筑后，旧请求即使成功返回也不得覆盖新页面。

分页每批最多 100 条，响应建议低于 512 KiB；具体大小以 UTF-8 字节数校验。必须包含总数、已加载数和下一批标识，不能只截断数据。索引变化使游标失效时明确重新获取，不拼接不同 revision 的结果。

在游戏侧按 cargo ID 建立“供应产业 / 消费产业 / 需求城镇”索引；C# 侧进行可见列表渲染和稳定排序。避免每次点击都进行全图两两匹配。

## 11. 刷新、作用域与性能

1. **按需读取**：打开页面、显式刷新或目录失效时启动索引任务。复用现有目录扫描结果；不在每个 350 ms 周期里重新全图解析配方与全部城镇。
2. **增量执行**：游戏侧读取只能在合适的游戏线程执行；将大型扫描拆成可中断批次，不能把游戏 API 放到不受支持的后台线程。
3. **一致性**：新索引在同一地图作用域内构建，完成后发布 revision；部分失败明确记录。刷新中可显示上次结果及“更新中”，不能把旧结果标成刚完成的新数据。
4. **地图隔离**：沿用 `MainForm.NameScope` 的连接/进程与地图会话隔离，并在索引建立、发布和动作执行前校验。地图、玩家或连接切换时取消旧请求，清空起点、历史、候选与游标。
5. **实体失效**：建筑被删除或产业关闭后，定位和继续分析重新核验；给出“目标已不存在，请刷新”，不误操作编号被复用的对象。
6. **不完整结果**：部分配方、城镇需求或坐标失败时，其余有效结果继续可用。单个实体异常不导致整个页面断线。
7. **持久化**：可保存布局与筛选偏好；首版不把产业实体编号和分析历史跨地图/游戏重启恢复。
8. **性能目标**：以约 1000 座产业、100 座城镇的合成地图数据验收；索引完成后，本地切换货物、搜索和排序目标为 200 ms 内反馈。游戏扫描单次批处理目标不超过 5 ms，超出时调整批量，记录实测而不是宣称已达标。
9. **交互**：等待数据时可继续搜索、滚动、切换本地分组；只按依赖关系禁用相关请求或定位按钮，不冻结全窗。

## 12. 空态与异常文案

| 情况 | 页面行为 |
| --- | --- |
| 尚未连接游戏 | 保留导航入口，提示“连接游戏并进入地图后，可查看产业推荐”。 |
| 尚未选择产业 | 展示手动选择与镜头推荐入口。 |
| 基础原料产业没有生产输入 | 显示“该产业无需生产原料”；可选增产材料另列。 |
| 没有已识别产物 | 区分“无产物规则”和“生产规则未读取”。 |
| 某种原料无供应者 | 显示“当前地图未找到生产该原料的产业”，不编造建筑。 |
| 某种产品无下游产业 | 显示空态，仍单独核查和展示供给城镇。 |
| 无有效建筑坐标 | 候选照常显示，距离为“未知”；保留其他可用操作。 |
| 城镇需求读取失败 | 显示失败数量和重试入口，其他产业关系仍可浏览。 |
| 数据分批读取中 | 显示“已加载 N / 共 M”；保持可滚动和继续加载。 |
| 镜头读取失败 | 保持当前分析起点，说明失败并允许重试。 |
| 游戏暂停导致请求等待 | 显示等待状态，避免重复提交，不锁死列表。 |
| 地图切换或目标删除 | 拒绝旧请求或动作，清理受影响状态。 |

| AC-14 | 多次“查看产业链”，再返回 | 恢复之前起点、货物与页面位置，历史循环不会触发递归失控。 |
| AC-15 | 镜头靠近不同产业，并设定分类筛选 | 点击镜头推荐选出筛选范围内最近产业，平时镜头移动不抢走手动选择。 |
| AC-16 | 仅镜头中心有效或镜头瞬时失败 | 中心有效时可推荐；失败时可重试且保留起点，不回退到未告知的旧读数。 |
| AC-17 | 正负坐标、真实零坐标、未知坐标、NaN、无穷值 | 有效坐标距离正确，未知排末尾且候选不消失，不产生假零距离。 |
| AC-18 | 101 / 1001 条匹配结果，或单批接近传输限制 | 所有批次可取完，计数正确，无静默截断、重复或 JSON 超限。 |
| AC-19 | 快速切换分析对象、刷新时 revision 改变、加载另一地图 | 旧响应不覆盖新选择，不混用索引版本，不复用其他地图实体。 |
| AC-20 | 定位前删除目标、断线、加载中或暂停 | 显示明确状态，不能误定位其他对象；列表仍可操作。 |
| AC-21 | 100% / 125% / 150% DPI，普通窗口、窄窗口与最大化 | 无裁字、越界、按钮遮挡或无法到达的结果；滚动恢复正常。 |
| AC-22 | 新功能关闭或新接口不可用 | 货物添加、世界管理、镜头书签与旧请求队列功能通过回归验证。 |

自动化重点覆盖规则方向、替代/增产语义、去重、完整集合、距离、分页、作用域和旧响应拒绝；WinForms 离线检查覆盖布局和状态。游戏实测至少完成“选起点 → 看全部供应者 → 定位 → 看全部产物去向 → 定位城镇 → 继续分析并返回”全流程。

## 14. 实施顺序与完成定义

1. 验证真实游戏 API 和样本，补齐产业类型、生产输入输出与城镇需求适配。
